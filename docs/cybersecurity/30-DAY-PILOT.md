# INNOVA Cybersecurity — 30-day controlled pilot
Updated: 2026-10-15. Status: prepared, no client testing or outreach sent.

## Commercial objective
Validate one paid CAD 990 External Security Review, qualify 2–3 larger audit opportunities, and establish at least one vetted pentesting delivery partner. All KPI figures are goals, not observed conversion rates.

## Positioning and buyer
Canadian mid-market / growth SaaS, e-commerce and professional service organizations. Buyer: CTO, technical founder, IT/security leader or COO. Security teams at large enterprises are not the primary pilot target.

## Pilot offer (indicative, subject to signed scope)
CAD 990 for a *small, clearly bounded* External Security Review:
- Initial intake and explicit identification of assets owned/operated by customer;
- Permitted public information analysis and external attack surface inventory;
- Manual confidence/ownership review; observation versus confirmed vulnerability marking;
- Prioritized written observations, risk hypotheses and fix plan;
- 30-minute asynchronous Q&A by email; a formal retest or exhaustive penetration test is not included.
- Any probing/validation beyond permitted public information requires signed Authorization to Test and exact asset allowlist, methods, dates and rate limits.

Potential upsell: separately scoped authorized external/web application pentest, remediation engineering, periodic surface monitoring. Never advertise security certifications or Mythos model use we have not earned/been authorized for.

## Anthropic program constraint

Official help article: https://support.claude.com/en/articles/14604842-cyber-verification-program
CVP grants cover the organization's own systems. **Client-facing security services using CVP access require a separate productization application and approval**; as of 2026-10-15 Anthropic says that application will be available in portal shortly. No client CVP use until separately approved. Public models and independently licensed tools may be used within their own terms.

## Four-week execution
- Days 1–3: product/contract templates, first-party source-review demo, shortlist of 8–15 public-company candidates, 2–3 white-label partner inquiries, write deliverable quality checklist.
- Days 4–7: assess own assets (read-only source review; live requests only within explicitly controlled scope); produce 1 representative example report; agree delivery partner conditions.
- Week 2: validate target fit and contact authority; research lawful outreach basis for each contact and log evidence; send only personalized compliant messages following final review.
- Week 3: customer intake, authorization and first paid review; third-party active tests only after agreement.
- Week 4: deliver verified report, propose fixes and monthly exposure review, measure win/loss and gross margin.

## Pipeline schema / gates
Prospect found -> target fit checked -> source relevance checked -> lawful outreach basis documented -> message reviewed -> contacted -> discovery -> scoped authorization signed -> passive review -> active tests if authorized -> report -> remediation quote -> fix -> retest -> monitoring.
Do not infer vulnerability from a domain, social-profile presence or old version string alone.

## Success metrics
Source of lead; number qualified; reply rate; meetings; signed reviews; contract value; direct specialist cost; time to deliver; false-positive ratio; remediation attach rate; monthly monitoring starts. The first 8 accounts are *research seeds only*, not qualified leads.

## Limitations
No external target active scans performed. No application submitted to Anthropic or productization program. No security partner signed. No commercial email sent. No production deploy. The landing is only a source branch candidate.
